## Executive Summary
This plan integrates the three operational pillars into Elyra's existing architecture (Phase 0/1 scaffolding with Kilo-driven agentic specialists, SQLite memory, MCP stubs, Conductor orchestration). It leverages current patterns (agentic specialists via Kilo CLI + personas + Pydantic schemas in `skills/agentic/`, `registry/personas/`, `models/site_schemas.py`) while adding GitHub org/repo automation, hybrid storage (SQLite + LanceDB + git-tracked artifacts + external media), and a multi-stage promotion pipeline with automated gates + single human approval.

Key integrations:
- Extend existing `deploy_specialist` persona + agent (already present) for GitHub repo creation under existing `Alira-os` org (https://github.com/Alira-os — Elyra project already lives here) + per-site repos.
- Wire hybrid storage into `memory/` layer and `conductor/memory_client.py`.
- Implement Promotion Pipeline as new `promotion_pipeline.py` orchestrator + updates to `security_gate.py` + Deploy Specialist.
- All changes follow validated agentic pattern: thin Python glue + Kilo CLI + persona + Pydantic.
- No new frameworks; reuse Kilo, MCP (GitHub, Fly.io), SQLite, LanceDB.

**Repo Creation Timing (user clarification):** Per-site repos are created ONLY when a site migration completes AND after the site has been built locally (not pre-provisioned).

Risks mitigated: Per-client org isolation trade-off accepted for pragmatism (first 50-100 migrations); media retention policy via Fly Volumes/R2 references only.

## 2. Implementation Plan by Pillar

### Pillar 1: GitHub Strategy (Alira OS Org + Per-Site Repos)
**Goal:** Automate repo creation/transfer under existing `Alira-os` GitHub org (https://github.com/Alira-os — Elyra already lives here). One repo per migration/client (e.g., `saint-joseph-the-worker-academy`). Repos created ONLY post-local-build when migration completes.

**Steps:**
1. Extend `deploy_specialist.md` persona (add GitHub org management, repo creation only after local build, transfer scripting, client portal via Discussions).
2. Create/update `skills/agentic/deploy_agent.py` (or new `github_strategy_agent.py`):
   - Thin glue: load SiteUnderstanding/Architecture + local build artifacts, build Kilo prompt for "Create repo under Alira-os org, push locally-built code, setup branch protection + Actions from templates".
   - Use GitHub MCP (wire real client in Phase 1) or Kilo GitHub tools.
   - Output: `DeploymentSpec` extended with `github_repo_full_name`, `org_transfer_script`.
3. Add Pydantic models in `models/site_schemas.py`: `GitHubRepoSpec`, `OrgTransferResult`.
4. CLI: Enhance `deploy.py` or new `github_strategy.py` with `--org alira-os --site-repo <name> --after-local-build`.
5. Wire into Conductor: After Builder/SEO finish + local build success (in promotion flow), invoke deploy specialist for repo creation.
6. Ownership transfer: Script `gh repo transfer` as final human-approved step.
7. Kilo tie-in: Auto-trigger Kilo Code Reviewer on PRs via GitHub Actions (add `.github/workflows/kilo-review.yml` template).

**Files to Create/Modify:**
- `registry/personas/deploy_specialist.md` (extend)
- `skills/agentic/github_strategy_agent.py` (new, follows scraper_agent.py pattern)
- `models/site_schemas.py` (add GitHub specs)
- `.github/workflows/` templates for Alira OS org policies.

**Dependencies:** GitHub MCP (Phase 1 wiring), `gh` CLI or GitHub MCP tools.

### Pillar 2: Storage Architecture (Hybrid Non-Negotiable)
**Goal:** Production-grade hybrid: Permanent metadata/provenance in SQLite + LanceDB; artifacts in git; media external (Fly Volumes / Cloudflare R2).

**Layers (as specified):**
- **Metadata + Provenance:** SQLite (`migrations` table extended with `migration_id`, `stage_history`, `fidelity_scores`, `persona_versions`, `decisions`).
- **Structured Artifacts:** JSON files in `memory/site_understandings/`, `memory/site_architectures/`, `memory/marketing_recommendations/` (git-tracked, permanent).
- **Code Artifacts:** Per-site Git repos (from Pillar 1).
- **Semantic Search:** LanceDB (vector embeddings of lessons + artifacts; query e.g. "Find all migrations that used a trades gallery").
- **Large Media:** Fly.io Volumes or R2 (store URLs only in metadata; retention "as needed").

**Steps:**
1. Extend SQLite schema (`memory/sqlite/schema.sql` or migrations in `crud.py`): Add `provenance` JSON column, `stage_history` array, `fidelity_history`.
2. Implement LanceDB layer (`memory/vector/lessons.py`): Embeddings for lessons, SiteUnderstanding summaries, architecture decisions. Use for Conductor routing queries.
3. Update `conductor/memory_client.py` + `skills/executable/memory_query.py`: Unified interface supporting hybrid queries (SQLite structured + LanceDB semantic).
4. Artifact persistence: After each specialist (scraper, architect, marketing), auto-save JSON to `memory/<type>/<migration_id>.json` (git commit).
5. Media handling: In Deploy Specialist, reference external URLs; add skill for R2/Fly Volume upload if needed.
6. Migration Ledger: Single source of truth table in SQLite for Project Manager queries.

**Files:**
- `memory/sqlite/schema.sql` (extend)
- `memory/vector/lessons.py` (implement full)
- `conductor/memory_client.py` (hybrid query support)
- Update `memory/memory.py` facade.

**Benefits:** Supports self-improving loop; avoids git bloat.

### Pillar 3: Promotion Pipeline (Refined & Hardened)
**Goal:** Builder + SEO → Kilo Reviewer + Security Gate → Preview Deploy → Human Approval → Production Deploy (Deploy Specialist).

**Flow (exact):**
1. Builder + SEO Specialist finish → Code pushed to Alira OS per-site repo (Pillar 1).
2. Kilo Code Reviewer + Security Agent run automatically on PR (GitHub Action).
3. Elyra SecurityQualityGate (Lighthouse ≥ 95, a11y ≥ 90, npm audit clean) as required status check.
4. Preview Deployment (Kilo native or Elyra preview Fly app) → Temporary public URL (7-day TTL) with banner: "Preview of new [Site] website".
5. Human Approval Gate (only mandatory human touchpoint) — "Good to go?" in PR / Slack / portal.
6. Deployment Specialist promotes:
   - Creates/updates Fly app (org/region)
   - Custom domain + SSL
   - Env vars & secrets
   - DNS update
   - Mark migration "Production Live" in SQLite ledger.

**Creative Enhancement:** Time-limited public preview with excitement banner.

**Steps:**
1. Create `promotion_pipeline.py` (orchestrator, thin glue calling Kilo for reviewer + preview deploy).
2. Update `conductor/security_gate.py`: Raise thresholds to ≥95 perf / ≥90 a11y; integrate Kilo reviewer output.
3. Extend Deploy Specialist persona/agent for full promotion steps (Fly app create, domain, secrets via Fly MCP).
4. Preview logic: New Fly preview app or Kilo deploy preview; post URL to PR.
5. Human gate: CLI prompt or GitHub PR comment listener.
6. Ledger update: On prod deploy success, update SQLite `migrations` with `production_url`, `live_at`.

**Files:**
- `promotion_pipeline.py` (new CLI/orchestrator)
- `registry/personas/deploy_specialist.md` (extend for promotion)
- `skills/agentic/deploy_agent.py` (extend)
- Update `conductor/security_gate.py`
- GitHub Action templates for reviewer + preview.

**Integration:** Triggered post-Builder in Conductor; uses existing Deploy Specialist.
